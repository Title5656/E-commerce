# ทดสอบและเผยแพร่ MONO V6

เปิด `tests.html` ในเบราว์เซอร์ ตรวจจำนวนผ่าน/ตกและค่าที่คาด ชุดทดสอบสร้าง storage ของตัวเอง ไม่เปลี่ยนข้อมูลร้าน เปิดจากไฟล์โดยตรงหรือ path ย่อยของ GitHub Pages ได้

รันกติกาจากเครื่องที่มี Node ได้โดยไม่มีแพ็กเกจ:

```text
node -e "require('./js/catalog.js');require('./js/rules.js');require('./js/store.js');require('./js/tests.js');Mono.runTests().then(r=>{console.log(r.filter(t=>!t.passed));console.log(r.filter(t=>t.passed).length+'/'+r.length);process.exitCode=r.some(t=>!t.passed)?1:0})"
```

## ผลตรวจบนเครื่อง · 22 พฤศจิกายน 2569

- baseline ก่อน V6: 30/30 จากชุดเดิม
- รุ่น V6: ชุดทดสอบ 47/47 ทั้ง Node และ tests.html
- เดินสี่เส้นทางจาก index.html: ซื้อเสื้อตรง ซื้อ Kit ใช้โค้ดซื้อเสื้อ และกลับมาซื้อบิลใหม่ ที่ 390/1440 พิกเซล
- ตรวจรหัสทั้งหกและหุ่นทั้งหกรุ่น กลับรุ่น/ไซซ์เดิม เมนูมือถือ ลิงก์ตรง refresh/back ไม่มีหน้าเกินความกว้างหรือทรัพยากรหาย
- เปิดสองแท็บจริง ใช้โค้ดพร้อมกันได้เพียงหนึ่งรายการและแยกที่มาลิงก์ของแต่ละแท็บ
- ปิด canvas เพื่อทดสอบภาพสำรองและตารางบนมือถือ เปิด file:// เพื่อตรวจ Kit/ทรัพยากรและ tests.html
- ภาพเสื้อใหม่ใช้ built-in ImageGen ทั้งหกรุ่น แปลง WebP 800 × 1000 พิกเซล ตรวจภาพและหน้าเว็บที่ใช้งานจริง
- ผู้ตรวจโค้ดแยกพบที่มาลิงก์รั่วข้ามแท็บ แก้พร้อม regression ที่เคยตกก่อนแก้แล้ว ไม่มีข้อสำคัญค้างจากรอบตรวจ

## เผยแพร่

GitHub Pages ใช้ `main` / `/(root)` และ `.nojekyll` หลัง push ต้องรอ deployment สำเร็จ แล้วเปิด URL สาธารณะทดสอบสี่เส้นทางและ tests.html ใหม่ ทรัพยากรเว็บต้องอยู่ใต้ origin/path ของโครงการ ไม่มี CDN/API จากหน้าเว็บ การตรวจบนเครื่องไม่ได้ยืนยันว่ารุ่น V6 เผยแพร่แล้ว
